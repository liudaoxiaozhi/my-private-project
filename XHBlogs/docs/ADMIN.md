# 网页后台（/admin）

打开 `你的网址/admin`，登录后就能在浏览器里（手机也行）管理整个博客：

| 板块 | 能做什么 |
| --- | --- |
| 概览 | 文章、杂谈、说说、歌曲、照片、友链、项目的数量；最近的修改；网站部署状态 |
| 文章 / 杂谈 | 写、改、删；Markdown 编辑器带工具栏、插图（可直接粘贴截图）、和网站一模一样的预览 |
| 说说 | 发说说，可以带多张配图 |
| 歌曲 | **网易云**：粘贴歌曲 / 歌单链接或 ID 导入（排在前面）；**本地**：上传 mp3（可带封面、LRC 歌词）。都能排序、置顶（第一首是默认播放的）、删除 |
| 弹幕 | 首页开场飘过的弹幕：增删改、开关 |
| 外观 | 背景插画（电脑 / 手机）、模糊、漫画风背景、实验室风格、黑胶播放器、首页开场文字、默认封面、各种特效开关 |
| 照片墙 / 友链 / 项目 | 增删改、排序、上传图片 |
| 账单 | 记账（新加坡元）：记一笔、按月查看和修改、分类与每月预算、CSV 导入导出；公开页只显示汇总统计 |
| 关于我 | 「关于」页正文 |
| 书影音与密钥 | 填 TMDB Key、Bangumi 令牌、Gemini Key（加密保存）；登录后台后，书影音页（/media）上就能直接添加和编辑，想看清单（/media/wishlist）上能「开始看」、移除 |
| 站点设置 | 名字、头像、简介、导航栏站名、社交链接、时区、天气、生日、备案号…… |

右上角「简洁」去掉背景插画和毛玻璃，手机上更省电。

## 网易云音乐

在「歌曲」里粘贴：

- 歌单链接：`https://music.163.com/#/playlist?id=123456`（手机 App 里「分享 → 复制链接」也行）
- 歌曲链接：`https://music.163.com/#/song?id=123456`
- 纯数字 ID：旁边选「歌曲 ID」还是「歌单 ID」；多个用逗号或换行隔开

点「解析并加入」后检查一下列表，再点「保存」。歌名、歌手、封面在导入时存进 `data/netease.json`，
播放时用网易云的官方外链，歌词由网站代取（缓存一天）。

需要知道的限制：

- **VIP / 付费歌曲**（列表里标了 VIP）外链放不了或只有 30 秒，播放器会自动跳过
- 有些歌曲有地区版权限制，在海外（比如新加坡）的访客可能放不了，同样会自动跳过
- 歌单最多导入 500 首；私密歌单读不到

## 自动播放

「外观 → 进入网站自动放歌」默认打开。浏览器（Chrome、Safari 等）不允许网页在访客没点过页面之前出声，
所以通常是访客第一次点击 / 触摸 / 按键时开始播放；访客自己按过暂停，这次浏览就不会再自动放。

## 书影音与密钥

「追番」已经扩展成「书影音」（`/media`，旧地址 `/anime` 会自动跳过去）：番剧、电影、电视剧、书和音乐都记在一起，
数据仍是 `data/anime.json`（整个书影音库）。另有「想看清单」（`/media/wishlist`），列出所有想看 / 想读 / 想听的条目，
按优先级排好，每条可以写想看的理由、在哪看（影院、B站、微信读书、网易云……）。

添加时按大类选搜索来源：

- 影视：Bangumi（动画 / 三次元）或 TMDB（电影 / 电视剧，要 TMDB Key）
- 书：Bangumi 书籍，或 Open Library（外文书更全，不用密钥）
- 音乐：Bangumi 音乐

都搜不到时可以手动填写。

线上的文件系统是只读的，所以以前写进 `.env.local` 的 TMDB Key、Bangumi 令牌在线上存不下来。现在：

- 在后台「书影音与密钥」里填，**加密后**存进仓库的 `data/secrets.json`（仓库里只有密文）。
  加密用的钥匙由 `ADMIN_PASSWORD` 派生（也可以单独设 `ADMIN_SECRETS_KEY`），所以**改了管理员密码后要重新填一次**，后台会提示「需要重新填写」
- 在 Vercel 环境变量里直接配 `TMDB_API_KEY` / `BANGUMI_ACCESS_TOKEN` / `GEMINI_API_KEY` 也可以，环境变量优先
- 登录了后台之后打开书影音页，就会出现「添加」和编辑按钮，保存同样提交到 GitHub；没登录的访客只能看

## 账单

在后台「账单」里记账，货币只有新加坡元（S$），数据在 `data/bills.json`。「今天」「本月」按站点设置里的时区算。

- **记账**：上方切换月份，看本月收入 / 支出 / 结余和预算进度；「记一笔」填日期、支出或收入、分类、金额、备注后按回车或「添加」
  （分类会记住上次用的）。下面的列表可以直接改、「复制」到今天、删除，可以按类型、分类、备注关键词筛选。
  所有改动点一次「保存」，一起提交
- **分类与预算**：增删改分类、设每月预算（留空 = 不设）。还有记账在用的分类不能删，要先把那些记账改到别的分类
- 金额保留两位小数（多填的四舍五入），单笔必须大于 0；备注最多 200 字

**公开和不公开的**：公开的 `/bills` 页只显示汇总——每年的收入、支出、结余、储蓄率，每月的收支柱状图，支出分类的金额和占比，
本月预算用了多少，以及最近一笔的日期。**单笔记账和备注只在登录后的后台看得到**，不会出现在公开页（包括页面源代码）里。
数据文件 `data/bills.json` 是**加密**存的（AES-256-GCM，钥匙和后台密钥相同：`ADMIN_SECRETS_KEY`，没设时用 `ADMIN_PASSWORD`），仓库里只有密文；
公开页在构建时用同一把钥匙解开、只把统计数字放进页面。旧的明文文件照样能读，下次保存自动加密。

**改管理员密码前一定要先设好 `ADMIN_SECRETS_KEY`**（并导出一份 CSV 备份）：钥匙变了旧账单就解不开。解不开时公开页显示「还没有记账」，
后台显示红色提示并拒绝保存（不会覆盖旧数据）；改回原来的密码 / 钥匙即可恢复。确实找不回时，可以在后台点「放弃旧账单，重新开始」，再用 CSV 导入。

**CSV**：「导出本月 / 导出全部」得到的文件带 UTF-8 BOM，Excel 直接打开不会乱码。导入用同样的格式：

```csv
日期,类型,分类,金额,备注
2026-10-09,支出,餐饮,12.50,午饭
2026-10-01,收入,工资,3000.00,
```

- 第一行是表头；日期 `YYYY-MM-DD`（`2026/10/9` 也认）；类型填「支出」或「收入」；分类填后台里**已有**的分类名；金额可以带 `S$` 和千位逗号
- 导入前会先预览：多少笔能导入、多少笔和已有记账完全一样（跳过）、哪几行有问题以及原因；点「合并」后再「保存」才会提交

## 它是怎么保存的

后台不用数据库。点「保存」时，它把这次改动的所有文件（文章、上传的图片……）做成**一个提交**推到 GitHub 仓库，
Vercel 收到提交后自动重新部署，**大约 1～2 分钟后网站更新**。后台页面顶部会显示部署进度，好了会提示「网站已经更新好了」。

- 文章、杂谈、说说还是 `posts/`、`chatters/`、`moments/` 里的 Markdown 文件，和以前一样
- 照片墙、友链、项目、账单在 `data/*.json`
- 站点设置：`siteConfig.ts` 里是带说明的默认值，后台改过的项保存在 `siteConfig.overrides.json`（只存和默认值不一样的部分）。
  想恢复默认，在后台点那一项旁边的「恢复默认」
- 上传的图片在 `public/images/uploads/年/月/`，会先在浏览器里压成 WebP（长边不超过 2400 像素）
- 歌曲在 `public/music/`，顺序就是文件名前的序号，调整顺序就是重新编号改名

因为一切都在仓库里，所以随时可以在 GitHub 上看到每一次修改、需要时回退。

> 以前电脑上的 `my-blog-manager`（本地管理器）不要再和网页后台混着用：它同步时会把整个 `posts/`、`siteConfig.ts` 等覆盖掉，
> 网页上做的修改就丢了。

## 部署到自己的服务器（宝塔面板）

除了 Vercel，也可以把博客放在自己的 Linux 服务器上（用宝塔面板管理），步骤见 **[DEPLOY-BAOTA.md](./DEPLOY-BAOTA.md)**。区别：

- 后台保存时**直接写进服务器上的文件**（`ADMIN_STORAGE=local`），不经过 GitHub，不需要 `GITHUB_TOKEN`；上传大歌曲也直接传给服务器
- 保存后网站**自动重新构建**（`SELF_HOST_REBUILD=1`），大约 1～3 分钟后上线。后台顶部显示进度，「概览 → 网站重建」显示
  排队中 / 重建中 / 已上线 / 失败，失败时能看日志，也能点「立即重建」。构建失败时线上还是之前的版本
- 内容由服务器每天备份推到 GitHub（`scripts/self-host/backup.sh`），代码更新由 `scripts/self-host/update.sh` 拉取
- 网站在 nginx 反向代理后面，要设 `TRUST_PROXY=1`，登录限流才能按访客的真实 IP 计算

## 开启步骤（只需要做一次）

### 1. 生成 GitHub 令牌

1. 打开 GitHub → 右上角头像 → **Settings** → 最下面 **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
2. 填写：
   - **Token name**：随便，比如 `blog-admin`
   - **Expiration**：选长一点（最长一年；过期后后台会提示「GITHUB_TOKEN 无效或已过期」，再生成一个换上即可）
   - **Repository access**：选 **Only select repositories**，只勾博客这个仓库
   - **Permissions → Repository permissions**：
     - **Contents**：**Read and write**（读写文件、提交）
     - **Commit statuses**：**Read-only**（读取 Vercel 的部署状态，不给也能用，只是看不到部署进度）
3. 点 **Generate token**，复制那串 `github_pat_...`（只显示一次）

### 2. 在 Vercel 里添加环境变量

Vercel → 你的项目 → **Settings** → **Environment Variables**，添加：

| 名称 | 值 | 说明 |
| --- | --- | --- |
| `ADMIN_PASSWORD` | 自己定一个**长一点**的密码 | 登录后台用。没设这个，后台整个不可用 |
| `GITHUB_TOKEN` | 上一步复制的 `github_pat_...` | |
| `GITHUB_REPO` | `用户名/仓库名`，比如 `liudaoxiaozhi/my-private-project` | |
| `GITHUB_BRANCH` | `main` | Vercel 部署的那个分支；不填默认 `main` |
| `GITHUB_BLOG_DIR` | `XHBlogs` | 博客在仓库里的文件夹；不填默认 `XHBlogs`。博客就在仓库根目录时填 `.` |
| `ADMIN_SECRETS_KEY` | （强烈建议）一串随机长字符，设好后别再改 | 加密后台密钥和账单用；不填就用 `ADMIN_PASSWORD`。设了它，改管理员密码时密钥不用重填、账单也照样解得开。后来才设也行：之前用管理员密码加密的内容照样能读，下次保存（账单保存一次、密钥任意保存一个）时换成新钥匙，换好之前别改管理员密码 |
| `NETEASE_API_BASE` | （可选） | 网易云接口地址，默认 `https://music.163.com`；服务器连不上网易云时换成自己的反代 |

加完以后到 **Deployments** 里点最新一次部署右边的 **⋯ → Redeploy**，让新变量生效。然后打开 `你的网址/admin` 登录即可。

### 安全说明

- 登录状态保存 7 天；改了 `ADMIN_PASSWORD` 后，所有已登录的设备都会被登出
- 同一个 IP 十分钟内输错 8 次密码会被暂时锁住
- 后台只能改上面列出的那些位置（文章、数据、设置、上传目录、音乐目录），改不了代码
- 超过 3MB 的音频是浏览器直接传到 GitHub 的（Vercel 的接口收不了 4.5MB 以上的请求），
  这时会把 `GITHUB_TOKEN` 临时交给已登录的浏览器用一次。所以令牌一定只给这一个仓库的权限，管理员密码也别太简单。
  自己的服务器上（本地存储）大文件直接传给服务器，不涉及令牌
- 限流用的访客 IP 和同源检查用的域名：Vercel 上由平台提供；自己的服务器上只有设了 `TRUST_PROXY=1` 才相信反向代理传来的
  `X-Real-IP` / `X-Forwarded-For` / `X-Forwarded-Host`（这些请求头谁都能伪造），见 [DEPLOY-BAOTA.md](./DEPLOY-BAOTA.md) 第 9 步

## 本地预览

本地 `npm run dev` 时，后台默认直接读写电脑上的文件（不经过 GitHub）。在 `.env.local` 里设好 `ADMIN_PASSWORD` 就能登录 `http://localhost:3000/admin`。
想在本地也走 GitHub，就把上面那几个 `GITHUB_*` 也写进 `.env.local`。

## 测试

`npm run test:e2e -- e2e/admin.spec.ts` 只跑后台的测试：后台写的是一份临时副本（`.e2e-admin-root`），不会动真正的文件；
GitHub 的提交流程用假的接口测，不会真的推送。
